# Purpose
This assignment shows off the basics of networking. We will create subnets of different sizes, assign each subnet a different VLAN (Virtual Local Area Network) and attach them to a switch. The switch will have each interface assigned the appropriate VLAN, and connect it to a router which will be a trunked link. The router will handle routing of inter-VLAN communication. 
This demonstrates:
- How to split a network between several VLAN
- IP addresses, subnet masks and gateway addresses
- Sub-interfaces
- Routing

*Why do we do this? 
By segmenting our network into VLANs and only allowing traffic tagged with a specific VLAN on each interface, we make sure no unauthorized traffic can flow through the network. 

*What does the trunk do?*
The trunk link blocks all traffic that doesn't have the VLAN header we specify. Again, this disables unauthorized traffic, but also enable all VLANs in the network to use this path to the router, where the VLAN header can be changed to allow it to reach its destination.

*Is this a real, viable network model?*
Yes! The "router on a stick" model as it's called is the simplest layout of inter-VLAN routing and is still used for smaller networks today. However, all traffic shares one path which becomes a bottleneck. A big network would not use this model, as it limits efficiency. 

# Scenario
We are building a simple network for an app-development company. Working under the assumption that the company will never shrink or grow, we need to build subnets that doesn't waste IP addresses for each section of the network. The company departments consists of:

Management: 10 employees
HR: 17 employees
Development: 180 employees

# Topology
As already described, the topology is small and simple. One central switch which is connected to 3 PCs and a router. Each PC uses a different VLAN. Check the packet tracer file for a visual topology.
Since standard switches work on Layer 2 of the OSI model (the Data Link layer) and handle frames, it contains no headers with IP addresses in them, instead relying on MAC addresses. This is fine when it comes to other directly connected Layer 2 network devices which uses the Spanning-Tree Protocol to map out the network topology. However, we need routing functionality; the option to receive data and figure out where it needs to go next. This is the role of our router. 

The name of each device is as follows:
PC in VLAN10: PC0
PC in VLAN20: PC1
PC in VLAN30: PC2
Switch: Switch0
Router: Router0

| 20  | HR          | /27           | 192.168.20.0    | 192.168.20.1 - 192.168.10.30  | 192.168.20.31     |

*What do CIDR notation and all these addresses mean?*
The CIDR notation says how many bits in a network IP address that are network bits ("reserved" bits that can't be changed) and host bits. In other words, it shows how big our subnet is. Commonly, local area networks have the CIDR notation /24, which means there's 256 addresses total and 254 useable addresses. This is because two addresses are always reserved; the network address identifies the subnet and is used for some network configurations like routing. The other reserved address is the broadcast address, an address that redistribute what is sent to it to the entire network. This is commonly used to find IP addresses of certain devices when a device doesn't know where the destination location of data.
**Important note!**
Since we use a VLAN address naming convention, meaning making the third octet of the IP identical to the VLAN ID, there are quite a lot of unused addresses between these subnets. This is commonly done in larger networks to make room for growth. We could just as easily put these three subnets in one /23 network. If we did (and started from 0 on the third octet) it would look like this:
DEVELOPMENT: 192.168.0.0 - 192.168.0.255
HR: 192.168.1.0 - 192.168.1.31
Management: 192.168.1.32 - 192.168.1.47
We would use 304 IP addresses for our subnets, meaning we still have 208 addresses left in our /23 network. Note that the Development VLAN appears first in this list: good practice lists the biggest subnet first.

*Why doesn't the router have a gateway address?*
The router is the gateway! A gateway is nothing more than a sign showing where data should be sent first to reach its final destination. Unlike the host that sends data, the gateway device knows exactly how big the network is and where every device is (unless configured otherwise) and takes charge of sending the data to the right destination.

*What does the x mean?*
The interface to the router will be split into three sub-interfaces that each use different addresses. This is the definition of router on a stick: by creating sub-interfaces on one physical interface, we can use this one path to regulate traffic from multiple VLAN. The x in IP address will match the VLAN ID, and the subnet mask will match the VLAN subnet mask. 

# Configuration proccess

## PC0-2
Not much configuration going on here, just the IP addresses, Subnet masks and Gateway addresses shown in the IP table.

## Switch0
1. The first thing we do is create our VLAN according to the VLAN table, meaning creating each vlan with an id number and setting the name of it. The hosts doesn't actually know what VLAN they are part of, its the switch keeping track of that by being told that everything beyond one interface is part of one VLAN. 
2. For each VLAN interface, we set the switchport mode to access and switchport access to corresponding VLAN. This is how the switch knows where the VLAN is in the topology. 
3. On the interface to the router, we set switchport mode to trunk. This changes the default state of allowing all traffic to block all traffic instead.
4. We set the switchport access to our 3 VLAN IDs. Traffic from and to them are now excluded from being blocked. 

## Router0
1. First of all we have to open the interface towards the switch with *no shutdown*.
2. We create each sub-interface. In my file, they use the Gig0/0/0 interface, so the command will be *interface gig0/0/0.X* where X is the VLAN ID. 
3. On each sub-interface, we start by encapsulating the interface with dot1Q for corresponding VLAN. The dot1Q stands for IEEE 802.1Q and is a standard that allows frames to be flagged with VLANs. In other words, this is what allows traffic to be flagged and flow properly. 
4. After encapsulation, we set the ip address to the gateway address and subnet mask of corresponding VLAN in the IP table. 

# Confirming network goals
- Each PC can ping each other successfully
- Each packet is tagged with the proper VLAN
- Each packet takes the expected route: from a PC to the router through the switch, which is then rerouted to the right destination through the switch
